# Receipt crop suggestions

Updated 2026-10-15. Implementation and production deployment configuration are part of the finance release candidate; deployment is pending.

Single-photo expense/liquidation/phone scans and batch image uploads use `receiptCropService.suggestReceiptCrop`. Liquidation row photo attachments now open the same editable corner preview before uploading; PDFs retain their existing attachment/parsing path. The employee confirms the suggested crop, adjusts corners, or selects Full photo. Original photos remain available during preview; this change does not add archival storage of both originals and cropped files.

Gemini receives a compressed preview (1280px maximum edge, JPEG where browser conversion succeeds). The server retains its API key and requests four whole-paper corners, excluding ambiguous/multiple-document guesses. Client and server reject missing/non-numeric/out-of-range, crossed/reversed, non-convex and near-zero crops. The client aborts a crop request after 12 seconds and falls back to local edge detection, then the full photo; it never silently applies a central crop after failed detection. Cropping/flattening stays in the existing client perspective-crop utility and happens only on confirmation. This does not approve expenses or change amounts/statuses.

Receipt parsing defaults to `gemini-3.5-flash-lite`, overridden by `GEMINI_MODEL`. Crop detection uses `GEMINI_CROP_MODEL`, then `GEMINI_MODEL`, then the same default. Crop detection defaults to 3.5 independently of `GEMINI_MODEL`, so the production receipt parser may remain on3.1 without downgrading crop suggestions; `GEMINI_CROP_MODEL` can explicitly override the crop model. IOCT Assist already used 3.5 Flash-Lite separately; Live voice settings are unchanged. Google lists 3.5 Flash-Lite as stable: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite . The existing SDK/dependencies are retained; access to this model was verified with a synthetic receipt image, without sending real customer receipts.

Local review on port3305 now permits authenticated POST `/api/receipts/detect-crop` and `/api/receipts/parse` as AI-only calls. OneDrive uploads, financial/evidence mutations and other business writes remain blocked, with startup user seeding disabled. The previous strict wrapper is backed up at `/tmp/ioct-live-review-before-crop-assist-20261015.cjs`. Do not interpret crop-preview success as permission to enable business writes.

Validation: geometry/model/default/override and Functions packaging tests; crop-service fallback/PDF/timeout, batch confirmation and row-attachment/full-photo tests; TypeScript/lint/build; actual authenticated Chrome synthetic row-attachment crop returned200 in about4seconds, with adjustable preview, Full photo reset and zero OneDrive uploads. Real receipt photos, employee roles and phone-camera/Safari behavior remain hands-on checks before rollout.
