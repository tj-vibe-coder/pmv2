Local implementation: 2026-10-14. Production endpoint inventory remains unverified. No live snapshots, writes, backfill or deployment were performed in this build session. Existing audit figures are dated source evidence, not fresh production assertions.

## Invoice evidence

Both root and checked-in Functions API copies mount `server/financeEvidenceRouter.js` at `/api/finance-evidence`. Functions runtime modules are generated by the existing predeploy packager; tests exercise an isolated generated bundle.

| Method / relative path | Contract |
| --- | --- |
| GET `/invoices/:id/documents` | Existing invoice required; returns bounded links (including unlinked history markers), shared document metadata, and legacy scan adapter. |
| POST `/links` | 1–50 unique invoice IDs; document ID or validated HTTPS/OneDrive metadata; allowlisted type, source, optional reference/date. Atomic, deterministic and retry-safe; duplicate active links preserve existing metadata. |
| PATCH `/links/:id` | Expected revision; source/reference/date correction or `active:false` plus reason. Unlinking allocated 2307 evidence requires explicitly zeroing the allocation first. |
| PUT `/documents/:id/certificate` | Expected document revision, printed values/period/review and full evidence allocation list. Same billed counterparty for positive allocations; retained zero allocations are audit-only for matching/party checks. Validates all invoice references before writes. Existing active BIR2307 link required. |
| GET `/:kind/:id/history` | Kind is `links` or `documents`; latest 50 immutable actor/time/before/after events. |

All require approved active users. Admin/superadmin write any invoice evidence; tax filers write BIR2307 only. User/viewer reads are allowed within the existing invoice surface. No payroll or outgoing entity types are enabled. Expected revisions reject stale edits with 409; invalid input uses 400, forbidden 403, missing source/document 404.

The existing OneDrive upload proxy accepts optional `financeEvidenceType`; that path checks active role/type, PDF/image extension and 25 MB decoded size before calling Graph, and returns the real drive ID. The client service's sentinel `server` is only a legacy API argument, never a persisted file identity. Other OneDrive consumers retain their existing behavior.

## Reimbursement parity

Focused parity covers GET `/api/reimbursements/:id/lines`, POST `/api/reimbursements/:id/pay-lines`, POST `/api/reimbursements/pay-lines-batch`, whole-form remaining payments and batch-mark remaining-amount semantics, with the funding-category helper recognizing `reimbursement_payments`. Existing `proofRef`, `transferId`, `paidAmount`, `paidRowIds`, CA restoration and best-effort investment sync behavior are retained. These are existing local payment features, separate from the new evidence-only APIs.

## Baseline and checks

Migration 001 derives an offline manifest from authorized snapshots, preserving source records and computing billed/cash/WHT/outstanding, historical reimbursement paid, CA remaining and investment totals in centavos alongside fingerprints. No source snapshot is fetched automatically. Fixture acceptance covers SI008 WHT/base and collection date, SI010 remaining unpaid, shared SI011/012/013 slip/cash and the 3,611.58 expected-certificate baseline. It does not introduce the Phase 3 incoming-payment ledger or separate bank dates.
